# Explicit Limitations & Dev-vs-Production Boundaries

To maintain strict engineering honesty, the following limitations and unexecuted distributed components are explicitly disclosed:

1. **Dockerless Verification Host:** On this Apple M4 Pro macOS workstation, Docker, Podman, Node.js, and host JVM runtimes are unavailable. Every runtime test, benchmark, chaos drill, and live UI capture ran natively via `local_native` (Python 3.12 + PyIceberg + DuckDB + SciPy Sparse CSR + FastAPI). The distributed artifacts (`docker-compose.yml`, `processing/spark/graphframes_social_job.py`, `processing/airflow/dags/social_graph_dags.py`, `sql/trino/social_graph_analytics.sql`, `infra/kubernetes/`) are statically syntax- and pin-validated, but were **not** executed live inside containers on this host.
2. **Measured Scale vs. Logical Billion-Edge Design:** Local benchmarks measured up to `194,343` events / `138,745` active edges (`stress` profile in `13.4 s`). True billion-edge scale requires executing `processing/spark/graphframes_social_job.py` across a distributed Spark cluster backed by Lakekeeper + S3 object storage (`docs/capacity-model.md`).
3. **Synthetic Ground-Truth Trust Evaluation:** Precision (`0.974`), Recall (`0.993`), F1 (`0.984`), and Celebrity FPR (`0/8`) are measured exclusively against deterministic synthetic adversarial cohorts (`bot_swarm`, `coordinated_ring`). Real-world social abuse exhibits adversarial adaptation, account compromise, and gray-area harassment requiring human-in-the-loop review, appeals workflows, and continuous adversarial red-teaming.
4. **Bronze Raw Log Retention vs. Crypto-Shredding:** `POST /v1/privacy/erase/{user_id}` synchronously purges all active edges, Gold features, communities, trust scores, DuckDB serving tables, and in-memory adjacency caches (`residual_active_edges == 0`). Historical immutable Bronze event logs and pre-erasure Iceberg snapshots still contain past `user_id` tokens until Iceberg snapshot expiration (`expire_snapshots`) and per-user KMS crypto-shredding are executed in production.
5. **Local OpenLineage & OpenTelemetry Transport:** In `local_native` mode, OpenTelemetry spans write to `.local_data/traces/spans.jsonl` and OpenLineage events write to `results/lineage/openlineage_events.json` rather than streaming live to external OTLP Collector / Marquez servers (configured in `docker-compose.yml`'s `observability` profile).
6. **Local Static Dev RBAC Keys:** Local development uses environment-configured static API keys (`viewer`, `analyst`, `admin`) to prove `401`/`403` enforcement. Production deployments must replace these with OIDC/JWT identity providers, short-lived mTLS, and secret manager rotation.
